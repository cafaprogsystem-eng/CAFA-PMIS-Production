## Progressive Web App (PWA) Architecture

### Service Worker

CAFA PMIS uses a Workbox-powered service worker generated by `vite-plugin-pwa` during the production build.

#### Why the service worker is disabled in development

The service worker is intentionally **disabled during development** (`devOptions.enabled: false` in `vite.config.ts`). This is standard practice for Vite PWA projects for the following reasons:

1. **Cache pollution prevention.** A service worker intercepts all network requests. In development, Vite serves assets from a hot-module-reload dev server that changes asset hashes on every file save. A running SW would cache these intermediate URLs and serve stale responses, breaking HMR and masking real errors.

2. **Faster iteration.** Without a SW intercepting fetches, browser devtools show the real network activity from the dev server rather than cached or SW-transformed responses.

3. **Predictable debugging.** Cache-related bugs (stale data, incorrect fallback) are much harder to diagnose when a SW is active. Disabling it in dev ensures that what you see in devtools is what the app actually does.

#### How to test offline behaviour

The service worker is automatically enabled when a production build is created:

```bash
# Build the app
pnpm --filter @workspace/cafa-pmis run build

# Serve the production build locally
pnpm --filter @workspace/cafa-pmis run preview
```

Then open the served URL in Chrome DevTools → Application → Service Workers to confirm registration. Use the Network tab's "Offline" throttle to simulate a disconnected state.

#### What the service worker caches

| Cache | Strategy | TTL / Cap | Contents |
|---|---|---|---|
| `cafa-api-cache` | NetworkFirst (8 s timeout) | 24 h / 200 entries | All `/api/*` responses |
| `google-fonts-stylesheets` | StaleWhileRevalidate | — | Google Fonts CSS |
| `google-fonts-webfonts` | CacheFirst | 365 days / 30 entries | Woff/Woff2 font files |
| Static precache | CacheFirst (Workbox default) | Versioned by build hash | JS, CSS, HTML, icons, splash PNGs |

#### Workbox configuration summary

- **`registerType: "autoUpdate"`** — new SW activates immediately on next navigation; no user prompt required.
- **`cleanupOutdatedCaches: true`** — previous SW caches are deleted when a new SW takes control.
- **`navigateFallback: "index.html"`** — SPA navigation requests are served from the cached shell when the network is unavailable.
- **`navigateFallbackDenylist: [/^\/api\//]`** — API calls are never served the SPA shell; they fall through to the NetworkFirst strategy or return a network error.

### Offline Data Layer (Dexie / IndexedDB)

A second caching layer sits below the service worker, implemented in `src/lib/offline/`:

| Module | Purpose |
|---|---|
| `db.ts` | Dexie schema — `syncQueue`, `apiCache`, `attachmentQueue` |
| `fetch-interceptor.ts` | Patches `window.fetch`; queues mutations when offline; serves GETs from Dexie cache |
| `sync-service.ts` | Processes the sync queue; sends `x-client-id` header for server-side idempotency |
| `storage-quota.ts` | Monitors IndexedDB quota; surfaces `toast.warning` / `toast.error` at 80 % / 95 % usage |
| `prefetch.ts` | Proactively warms 11 critical API endpoints after login and after reconnect |
| `attachment-store.ts` | Tracks offline file uploads; stores metadata in Dexie, binary in memory |

#### Storage quota monitoring

`checkStorageQuota()` uses `navigator.storage.estimate()` to measure combined IndexedDB + Cache Storage usage relative to the browser's origin quota. It is called alongside `prefetchCriticalData()` on mount and after reconnection. Checks are rate-limited to once per hour to avoid performance impact.

Thresholds:

| Usage | Notification |
|---|---|
| ≥ 80 % | `toast.warning` — amber, 8 s, dismissible |
| ≥ 95 % | `toast.error` — red, 12 s, links to Sync Status page |

### Authentication & Session

- **Cookie:** `cafa_sid` — `httpOnly`, `sameSite: lax`, `secure` in production.
- **Session secret:** `SESSION_SECRET` environment variable (required in production; a loud warning is logged if absent).
- **Middleware order (routes/index.ts):**
  1. `attachCurrentUser` — parses session cookie / dev header; populates `req.currentUser`.
  2. `authRouter` / `healthRouter` — public endpoints (no auth required).
  3. `requireAuth` — rejects unauthenticated requests with 401.
  4. `idempotencyMiddleware` — replays cached responses for duplicate `x-client-id` requests. Runs after auth so replay is gated on a valid session.
  5. Resource routers — `meRouter`, `projectsRouter`, `reportsRouter`, etc.

### Deployment Checklist

See `replit.md → Deployment Guide` for the full checklist. Key PWA-specific steps:

1. Set `BASE_PATH` to the deployment root (e.g. `/`) — controls `start_url` and `scope` in the web app manifest.
2. Run `pnpm run typecheck` — must pass with 0 errors before deployment.
3. Test offline behaviour against the production build (`pnpm build && pnpm preview`).
4. Verify SW registration in Chrome DevTools → Application → Service Workers after first load.
5. Confirm iOS Add to Home Screen shows the correct splash screen and icon (test on a real device or Xcode Simulator).
