# CAFA PMIS GitHub handoff manifest

## Purpose

Use this manifest when creating the authoritative GitHub repository. It defines
what belongs in the handoff, what must remain local, and which documents govern
operations after transfer. It contains no credentials or environment values.

## Include as tracked release source

| Boundary | Include |
| --- | --- |
| Application | `artifacts/cafa-pmis/` and `artifacts/api-server/`, including source, tests, Vite/Playwright/Vitest configuration, and package manifests |
| Shared contracts | `lib/`, including `api-spec`, generated client/Zod sources, and committed declaration output |
| Database | `lib/db/`, `artifacts/api-server/src/migrations/`, and the canonical migration runner/tests |
| Tooling | root `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, TypeScript configuration, `scripts/`, and `docker-tools/pnpm-10.26.1.tgz` |
| Container and infrastructure | `Dockerfile`, `.dockerignore`, `docker-compose.yml` as local-only reference, `infra/aws-staging/`, and `.github/workflows/` |
| Configuration templates | `.env.example` and `.env.production.example` only |
| Release evidence assets | eight sidebar baselines, four approved landing WebP captures, their provenance JSON, and their capture/guard tests |
| Documentation | `README.md`, `HANDOVER.md`, `DEPLOYMENT.md`, `BACKUP_RESTORE.md`, `PWA_AUDIT_REPORT.md`, `docs/`, and this manifest |

Generated API declarations under `lib/api-client-react/dist/` and
`lib/api-zod/dist/` are intentionally tracked: contract-drift CI depends on
them. Do not delete them as ordinary build artefacts.

## Exclude from handoff

The following must not be committed or copied into a release image:

- populated `.env*` files, private keys, certificates, service-account files,
  secret stores, session cookies, database URLs with passwords, and provider
  credentials;
- `node_modules/`, build outputs, caches, local logs, test results, screenshots
  generated by test runs, and local editor metadata;
- Replit local state such as `.local/`, `.cache/`, `.replit*`, and private
  workspace data;
- database backups, SQL dumps other than tracked migrations, local PostgreSQL
  volumes, and exported production data;
- AWS staging operator state, plans, generated templates, logs, CLI history, and
  unredacted task definitions;
- non-production fixture descriptors, `attached_assets/Pasted-*.txt` planning
  inputs, hidden `.Pasted-*` editor remnants, and historical release archives.

`.gitignore` and `.dockerignore` enforce the main exclusions. Check both, then
run `git status --short --untracked-files=all` and `git diff --check` before
transfer.

## Handoff execution checklist

1. Run the local quality gates in [README.md](../README.md#local-quality-gates)
   on a clean checkout with `pnpm install --frozen-lockfile`.
2. Confirm the working tree contains no staged, unstaged, or untracked release
   files outside the intended commit.
3. Scan the proposed commit without printing suspected values. If any historical
   secret exposure is possible, rotate the relevant deployment, database,
   session, storage, email, AI, and test credentials before remote use.
4. Commit the generated contract declarations, migration files, eight sidebar
   baselines, four approved landing assets, and provenance metadata together
   with any source change that requires them.
5. Create the remote repository with protected `main`, required CI checks,
   pull-request review, linear history, and restricted force/direct pushes.
6. Configure CI-to-AWS access through a narrowly scoped, environment-protected
   GitHub Actions OIDC role. Do not store long-lived AWS keys as Actions
   secrets.
7. Record source revision, CI run, image digest, migration intent, staging
   evidence, and promotion approval in the change record. A source SHA or
   mutable image tag is not a production identity; the immutable image digest
   is.
