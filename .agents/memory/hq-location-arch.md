# HQ Location Architecture

## Rule
HQ is stored as `location_type = "hq"` on each record. It is **never** a row in `states` and is **never** inferred from `state_id = NULL` alone.

**Why:** NULL state_id predates HQ; historical records have NULL for other reasons. Explicit column avoids semantic collision.

## Schema (Migration 013)
- `reports.location_type TEXT`, `activities.location_type TEXT`, `plans.location_type TEXT`, `risks.location_type TEXT` — "hq" | "state" | NULL
- `plans.state_id` and `risks.state_id` — DROP NOT NULL (now nullable for HQ records)
- `users.office_location TEXT` — staff base location (separate from permission scope stateId)

## API response layer inference
All SELECT queries use:
```sql
COALESCE(r.location_type, CASE WHEN r.state_id IS NOT NULL THEN 'state' ELSE NULL END) AS "locationType"
```
Applied in: risks.ts (riskSelect), plans.ts (planSummarySelect), reports.ts (reportSelect).

## Backend validation
- locationType=hq + stateId present → 400 invalid_location_combination (risks, plans, reports)
- locationType=hq for non-activity report types → 400 (reports.ts)
- State-scoped roles (SPO, SOM) attempting HQ create → 403 hq_forbidden

## Shared frontend helpers
- `lib/location.ts`: LocationScope discriminated union + inferLocationType()
- `lib/format.ts`: formatLocation({ locationType, stateName, stateId }) — ONLY place HQ/State label logic lives
- `components/location-selector.tsx`: Select with HQ group above States; isStateLocked for state-scoped users; HQ_SENTINEL = "__HQ__"

## Permission (frontend)
- risks.tsx: isStateLocked={isStateRole}, auto-fills meStateId on dialog open
- create-plan-registration-dialog.tsx: wraps HQ SelectGroup in {!isStateRole && ...}

## HQ plan codes
Format: CAFA-PLAN-HQ-NNN. Generated by generateHqPlanCode() in plans.ts.

## Display
Always call formatLocation() for state/location display. Never inline `locationType === "hq" ? "HQ" : stateName`.
