---
name: Orval codegen duplicate-export conflict
description: How to avoid TS2308 duplicate export errors when orval generates both Zod consts and TypeScript interfaces with the same name.
---

## The Rule

When adding OpenAPI request-body or params schemas, use `$ref` pointing to a **differently-named** component schema so the Zod const name (derived from operationId) never matches the TypeScript interface name (derived from schema ref).

**Example — BAD (creates conflict):**
- Schema ref: `$ref: "#/components/schemas/CreateConversationBody"`
- operationId: `createConversation`
- Orval generates: Zod const `CreateConversationBody` AND TS type `CreateConversationBody` → TS2308

**Example — GOOD (no conflict):**
- Schema ref: `$ref: "#/components/schemas/ConversationInput"`
- operationId: `createConversation`
- Orval generates: Zod const `CreateConversationBody` (from opId) + TS type `ConversationInput` (from schema) → no clash

## The Barrel Fix

The `schemas` option in `orval.config.ts` (zod output) generates TypeScript interfaces alongside Zod validators. Those interfaces are re-exported from the generated barrel and can collide with Zod const names. Removing `schemas` from the zod output config eliminates TypeScript interface generation entirely — consumers use `z.infer<typeof Schema>` for types.

**Current config (`lib/api-spec/orval.config.ts`) — zod section:**
```ts
output: {
  workspace: apiZodSrc,
  client: "zod",
  target: "generated",
  // schemas option intentionally OMITTED — prevents TS2308 duplicate exports
  mode: "split",
  clean: true,
  ...
}
```

## Why

Orval generates TypeScript interface names from the `$ref` schema name, and Zod const names from the operationId + body/params suffix. When inline request body schemas are used (no `$ref`), orval generates the same name for both → TS2308 in the barrel.

## How to Apply

1. For every new request body, use `$ref: "#/components/schemas/XyzInput"` (never suffix with `Body`).
2. For query params schemas, avoid inline schemas on operations with both path + query params — orval may generate conflicting Params names.
3. Never re-add `schemas` to the zod orval config output without testing for name conflicts.
4. `lib/api-zod/src/index.ts` is regenerated by orval each time codegen runs — do NOT manually edit it. The fix is structural (remove `schemas` from config).
